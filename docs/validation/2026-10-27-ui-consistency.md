# 页面、卡片、主题与时间排序验证

日期：2026-10-27。集成基线：GitHub main `d4bcd0b`。本次 UI 变更在独立 PR 分支验证；新增 agent-browser 条目来自已有主线，PR 不修改技能源或译文。

## 审视结论与调整

- 原推荐卡片在首页、推荐目录、主题页、技能相关推荐和搜索结果有独立 DOM 与样式；现统一为 `RecommendationCard.astro`，搜索通过模板克隆相同结构。
- 技能和推荐卡片共享 `content-card`，统一表面、内边距、标题、摘要、标签和页脚；主题标签使用站点已有中文名称，页脚展示作者／适用 Agent、本站收录／发布时间和操作入口。
- 技能／推荐目录移除与主标题重复的眉题；详情页使用一致的日期元信息和辅助资料区域；贡献页由窄右栏改为居中的完整表单区，可选推荐信息采用响应式网格。
- 导航末端增加图标式主题按钮，原生 popover 提供浅色、深色、跟随系统。默认跟随系统；手动覆盖保存到 `hwskill-theme`，选择系统删除覆盖。首屏内联恢复脚本、CSS `light-dark()` 与 Tailwind dark 变体使用同一有效主题。Oklch 颜色与圆角保留 preset 值。
- 用户明确选择首次收录／发布时间。使用 Git 首次添加历史，不使用文件修改时间，兼容条目层级移动及推荐格式迁移。无 Git／浅克隆回退到版本化日期快照；未知时间稳定排后、不伪造日期。分类导航、分组和流程步骤保留语义顺序。
- 首页、目录、主题页、相关推荐及筛选／搜索的候选展示均按时间倒序。同时间按 ID 稳定排序，关键词相关性仍决定候选集合。只增加站点视图元数据，没有改变业务 Schema 或机器数据契约。

## 发现并处理的问题

共享推荐卡片增加的辅助信息改变了技能详情的索引权重，曾使“性能优化”多匹配 Spark 条目。通过将相关推荐区及日期元信息从详情正文索引排除来修复；原阈值和搜索预期没有放宽，原有 38 个门禁案例全部通过；同步最新主线后完整 39 个案例再次通过。

真实 Git 日期测试需要 Node 创建临时 Git 仓库，沙箱内遇到 `spawnSync git EPERM`。最终完整 Node 测试在允许启动临时 Git 子进程的环境中执行通过。系统主题变更事件异步触发，浏览器测试等待有效主题变化后断言，没有使用固定延迟。

浏览器验证使用 Linux Chromium；没有声称完成所有操作系统浏览器实测。字体沿用此前 Public Sans + 本地优先中文字体 + 同源 Noto Sans SC 的方案。
