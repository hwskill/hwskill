# 跨项目技能共享平台需求规格

日期：2026-09-11

状态：已确认产品方向与提交流程，完成需求细化供评审；未实施。本文中的自动化和验收条款均为目标行为，不表示已具备相应能力。

技术设计见同目录 `2026-09-11-skill-sharing-technical-design.md`，包含推荐选型、组件契约、发布一致性、迁移与分阶段验证。

## 1. 目标与边界

帮助员工发现、查找、安装和推荐可跨项目使用的技能。主要流程为：发现技能 → 判断适用性 → 复制一句话交给 Agent 安装 → 使用后反馈或推荐。

### 首要产品原则（已确认）

极力降低员工推荐技能、发现技能、安装使用技能的成本，增加员工发现技能的机会，同时降低维护者的日常运营成本。功能取舍优先看能否减少参与者的总操作、理解和等待成本，或让有用技能更容易出现在日常工作入口；不能仅把员工的工作转交给维护者。

- 推荐：员工提交一个技能链接即可，推荐理由和使用经验选填；也可把来源和贡献指引交给 Agent，由 Agent 整理条目和准备贡献。不要求员工本人理解 L1–L5、填写 YAML、操作 PR 或承担技能维护责任。
- 发现：同时服务主动查找和偶然发现；按目的表达用途，通过群分享、首页推荐、主题精选和相关技能增加触达机会。
- 安装使用：主要操作是复制一句话交给 Agent；合理默认值、环境识别、依赖检查和安装后检查承担复杂性，并提供首次使用示例。
- 维护：常规提取、默认值生成、去重、校验和发布交给系统；维护者集中处理异常和必要判断。无法自动确认的内容如实标记，不编造补全，也不要求逐字段人工重填。
- 触达质量：增加有用的曝光，不以重复刷屏或强制订阅换取曝光数量。

首版包括：

- Git 维护技能目录，保留 L1–L5 分类。
- 网站浏览、关键词搜索、多维筛选和技能详情。
- 本仓库托管技能与外部引用技能；外部技能不在仓库备份正文。
- 根据结构化安装信息生成一句话安装指引。
- 分层验证记录与失效状态展示。
- 新技能和推荐发布后，Python 信息模块可在高区主动读取蓝区信息，输出供后续本区 bot 消费的数据；本期完成到信息提供为止。
- 已收录技能可独立发布后续推荐帖，支持一篇推荐关联多个技能，复用网站和群分享链路。
- 初版收录 5–10 个开发者技能，偏重通用计算、智能计算、性能优化、大数据、C++/Python，并可包括制作 PPT 等常用周边技能；保留更广候选的调研依据和暂缓理由。

本期信息模块交付边界：通过 Python 获取、检查、筛选发布信息，判断增量、去重并提供结构化输出和恢复能力。提交给 bot 的 SDK/HTTP 方式后续确定；本期不实现发送框架、bot 桩、平台签名或群卡适配。

首版不包含使用遥测、个性化推荐、跨区推荐数据汇总或新的统一技能运行时。取消必须选择 Profile 才能使用技能的产品流程，但保留用途和场景标签。L1–L5 表达能力类别，不表示质量等级；L5 业务场景技能仍可收录。

沿用现有分类含义：L1 通用任务编排、L2 研发工程、L3 性能工程、L4 芯片亲和、L5 业务场景方案。分类由 Agent 建议、维护者必要时调整，员工不必先理解分层才能推荐或查找。

## 2. 架构与事实源

蓝区 Git 是人工维护的技能描述、安装声明和本地技能正文的事实源。发布流程从同一 Git revision 校验条目、生成网站索引和通知事件。

```text
蓝区 Git → 校验 → 网站及索引发布 → 发布只读通知事件
                                      ↑
黄区 Python 任务 ─ 静态发布信息只读拉取 ─┤ → 结构化输出 → 后续接入黄区 bot
绿区 Python 任务 ─ 静态发布信息只读拉取 ─┘ → 结构化输出 → 后续接入绿区 bot
```

每个区域独立保存信息获取与交接进度；后续接入 bot 时，群凭据和反馈也保存在本区。蓝区不主动调用高安全区 WebHook。浏览器、Agent 和机器人读取可直接访问的静态站点及其发布元数据，无需 AccessToken；只有读取非公开仓库等受限来源时才按其权限配置认证。本期部署验收验证静态信息读取和确有需要的私有仓库读取；本区群发送留待后续接入时验收。Token 不替代网络连通性。

平台生成的验证产物单独保存，带来源与执行时间；不可用与零值不同。第三方 Star badge 仅负责展示，不要求平台采集或维护更新时间。

## 3. 技能条目与贡献模板

建议目录：

```text
entries/l1/<namespace>/<name>.yaml
entries/l2/<namespace>/<name>.yaml
...至 l5
skills-src/<layer>/<namespace>/<name>/  # 仅本仓库托管正文
```

稳定 ID 采用 namespace/name，不随分类移动而改变。每个技能只有一个目录条目；网站索引由条目生成，不手动维护第二份描述。

以下是发布条目的维护模板，不是要求员工手工填写的推荐表单。字段由员工使用的 Agent 或平台提取、生成，维护者复核；员工可自愿补充：

| 字段 | 要求 |
| --- | --- |
| ID、名称、简短介绍、layer | 必填；ID 唯一，layer 为 l1–l5 |
| 解决的问题、适用场景、使用示例 | 必填；示例说明输入任务和预期结果 |
| 来源类型 | hosted 或 external |
| 来源定位 | hosted 为仓库相对目录；external 为源地址、技能路径或正式安装入口 |
| 安装方式 | 目录安装或上游安装机制；说明单技能或整包安装范围；无法确定时明确标记仅收录，不生成可执行安装指引 |
| 版本选择 | 可固定的来源声明期望 ref；实际验证记录保存解析后的不可变版本 |
| 支持的 Agent、系统、依赖、账号要求 | 必填；未验证与不支持分开表达 |
| 目录维护人 | 默认使用目录统一负责团队，不逐条指派推荐者 |
| 许可证或使用限制 | 必填；未知显式标记 |
| 关键词、不适用条件 | 建议填写 |

推荐理由是可选投稿内容，提交时转换为独立推荐帖，不在技能条目里重复保存。没有理由时直接使用来源支持的用途说明展示技能，不要求维护者补写。已验证版本、日期、Agent 版本、环境、结果和证据由验证流程产生，不要求普通推荐者填写。

主要提交流程：员工提供来源或推荐内容 → Agent 准备变更并本地校验 → 在员工已授权且具备权限时提交 PR → CI 检查 → 维护者审阅合入 → 自动发布网站 → 生成事件供本区 Python 任务获取，后续可接入 bot 分享。仅提交链接的轻量入口经批量 Agent 整理后进入同一 PR 流程。本仓库托管的新技能也可由作者提供正文或所在位置，通过同一流程生成条目。

常规条目由员工使用的 Agent 或平台生成稳定 ID、建议分类与关键词、来源定位及可提取的安装声明，并附提取依据。分类与摘要建议允许维护者修改；不确定的兼容性、许可证和验证状态显式保留未知。缺少可安装定位时进入待补充队列，不生成看似可用的安装按钮。不执行未经隔离的上游安装脚本来补全元数据。

维护者在一个审阅入口看到原始链接、生成差异、重复检测和失败检查，不需往返填写模板、手工重建索引或转发群消息。首版保留合入前的简短审阅，常规条目可批量处理；精选推荐理由和复杂安装方法才需要额外判断。自动合入不作为首版前提。

首版必须提供所在区域可用的轻量线索接收入口，可利用已有群或表单。元数据整理和检查至少提供一次触发的自动处理入口，不把人工逐条转录作为常态；自动建 PR 可随平台权限后续接入。提交后明确告知已收到、已收录链接或后续处理状态；重复推荐复用既有条目，不要求员工重新填写。详细模板作为维护者和高级贡献者的可选入口。

仅收录、待验证的技能可以发布，但不显示安装或行为验证通过。推荐接收与正式发布分开，验证不阻塞员工提交线索。高安全区推荐内容先留在本区，经现有允许的信息流转流程处理；不假定表单或维护者能够直接把高安全区内容写回蓝区。

### 3.1 通过 Agent 贡献

首版提供面向员工和 Agent 共用的贡献指引，让员工可以直接复用已有 Agent 完成贡献。链接推荐、Agent 辅助贡献和直接 PR 三个入口采用相同条目契约和校验，不维护三套格式。元数据整理可先由员工侧 Agent 完成，不强制先建设中心化信息提取服务。

仓库与网站提供以下材料（本节定义待实现产物）：

- 稳定的贡献指引入口：解释来源类型、L1–L5 分类、贡献流程和提交方式。
- 机器可读的条目 Schema：字段含义、必填项、枚举、默认值和未知值表达，包含格式版本。
- hosted/external 两类模板及有效示例：分别说明正文托管与外部引用；模板和示例在 CI 中按同一 Schema 校验。
- Agent 操作指引：读取索引去重、从来源提取信息、生成文件、执行检查、整理变更摘要和提交准备。
- 可在本地执行的确定性校验入口及与 CI 一致的错误输出，便于 Agent 自行修正格式问题。

网站提供可复制的一句话：

> 请按〈贡献指引链接〉，将〈技能链接或本地技能目录〉整理为技能贡献，检查是否已收录，按模板生成条目并运行校验，完成提交准备；只有必要信息无法从来源确定时再问我。

Agent 的预期流程：

1. 读取贡献指引、Schema 和现有索引，定位用户指定的单个技能；来源包含多个候选且无法确定时再询问。
2. 检查是否重复，已收录时返回现有链接；新的使用经验生成推荐帖，事实信息修正才更新原技能条目。
3. 提取有依据的元数据，按模板生成条目；hosted 整理完整技能目录，external 仅生成引用。来源正文作为待分析材料，不得覆盖贡献指引或诱导无关操作。
4. 运行本地校验并修复确定性问题，准确报告已运行、未运行和环境受限的检查，不编造使用经验或验证通过记录。
5. 输出变更摘要、来源依据和检查结果。在当前区域允许写入目标仓库、具备权限且用户已授权提交时，可继续提交 PR；否则保留可审阅的本地变更并说明具体下一步。

通过 Agent 贡献不要求先安装专用贡献技能或平台运行时。后续可把相同指引封装成可选技能，但基础入口始终可直接读取。高安全区 Agent 生成的文件仍留在本区；使用 Agent 不改变跨区写入与信息流转规则，也不使用通知机器人的只读 Token 承担贡献写入。

### 3.2 提交入口、权限与过程反馈（已确认）

| 网站入口 | 员工最少输入 | Agent 生成的变更 |
| --- | --- | --- |
| 收录技能 | 来源链接或自研目录 | 新条目，hosted 同时提交完整正文 |
| 发布推荐 | 技能链接与一句理由 | 推荐帖；多技能主题帖引用多个技能 ID |
| 修正信息 | 技能链接与修正内容 | 更新原条目，不创建重复技能 |

网站按钮复制含上下文的贡献提示词，不保存 Git Token，也不声称点击复制已经提交数据。Agent 以员工已有认证，在有权限的同仓分支或 Fork 中准备 PR；采用哪种方式由实际 Git 平台权限决定。授权在会话中已明确时不反复确认；未授权发布时先交付可审阅的变更。

用户看到的过程状态及其证据：

| 状态 | 依据 | 员工下一步 |
| --- | --- | --- |
| 已准备 | 本地变更与校验报告 | 查看摘要；尚未提交时决定是否提交 |
| 已提交／待修正／待审阅 | 真实 PR 链接与 CI 结果 | Agent 修正问题或等待审阅 |
| 已合入／发布中 | 合入记录与发布任务 | 无需重复投稿 |
| 已发布 | 实际可访问的技能或推荐详情 | 安装、使用或分享 |
| 发布受阻 | 发布任务失败信息 | 由维护者处理基础设施问题，不让投稿者重建 PR |
| 未采纳／已关闭 | 接收入口或 PR 的处理说明 | 查看原因，可补充资料后再次提出 |

不为以上状态新建投稿数据库；准备结果由 Agent 报告，提交后以 Git/CI 为准，发布结果关联网站地址。仅提供线索的员工通过原接收记录获得 PR 或已有技能链接；自动回写不可用时支持维护者批量反馈，不承诺不存在的全自动通知。

缺少认证、写权限或允许的信息流转渠道时，Agent 保留本区变更/补丁并报告阻碍，不显示“已提交”。不得通过代理账号自动绕过高区到蓝区的写入边界。

## 4. 网站发现与搜索

首页提供新收录、精选推荐、近期更新和按目的浏览。精选以可解释的推荐理由和验证证据为依据，不把上游仓库 Star 当成技能质量分数。

员工无需先理解分层或技能名称。卡片以“能帮你完成什么”开头，配一个简短例子，直接提供详情、复制安装指引和分享入口。按目的组织主题精选，详情页展示相关技能；已有技能也可以凭新的使用案例进入精选，避免只有新增技能才有曝光机会。主题精选只是浏览内容，不恢复必须选择 Profile 的流程。

列表支持搜索名称、介绍、目的、关键词和示例，并按 L1–L5、Agent、来源和验证状态筛选。首版采用关键词和同义词搜索；按使用反馈决定是否增加语义搜索。

详情页展示：解决的问题、适用与不适用条件、示例、推荐理由、来源、安装范围、依赖、复制安装指引按钮和验证记录。外部资源失效时保留条目并明确提示，不继续呈现为当前可安装。

推荐列表和推荐详情也是首版页面。技能详情展示关联推荐，新推荐不要求技能版本更新。浏览、搜索不要求业务登录或授权 Git 写入，但服从所在网站已有访问控制。

搜索无结果时给出换词、清除筛选或推荐新技能入口；“安装说明不明确”“暂时不可获取”“已撤回”均提供具体状态，不能留下不可解释的失效按钮。复制失败时展示可手选文本；无脚本环境至少仍可阅读技能、来源和说明。搜索内容限已发布条目、公开可读的推荐和用途信息，不索引草稿或凭据。

## 5. 一句话安装

指引示例：

> 请按照〈技能安装说明链接〉，将〈技能名称〉的已验证版本安装到当前项目，并检查完整文件、依赖和 Agent 识别情况；完成后报告安装位置与验证结果。

网站默认项目级安装，可切换用户级范围。指引和说明来自结构化声明，版本、目标 Agent 和安装范围必须一致。未验证技能明确标注待验证，不使用“已验证版本”措辞。

默认路径不要求员工先安装本平台 CLI、配置 MCP 或选择 Profile。Agent 可识别的环境自动识别；只有无法确定且影响安装结果的事项才询问员工。必要的宿主认证或重启给出具体下一步，不能假设可以自动完成。安装完成后提供可直接尝试的首个任务示例；发现依赖缺失或安装失败时给出可操作的修复说明，减少员工自行排查的成本。

安装契约：

- 获取完整技能目录或调用上游声明的安装机制，包含脚本、引用文档和资源。
- 整包安装须预先展示附带技能和配置影响。
- 不静默覆盖同名技能或无关用户配置；冲突时说明处理选择。
- 安装结束报告实际来源、revision、安装位置及检查结果。
- 已验证固定版本与上游最新版本区分展示，不把旧版本验证结果转移给新版本。

外部源可以在临时验证环境下载，结束后清理正文。仓库只保存引用和验证证据，不保存外部正文备份。固定 revision 不能保证上游永远保留内容；外部删除或网络不可达仍会使安装失败。

技能可处于正常收录、已弃用或已撤回三种运营状态，与安装验证状态分开。弃用展示原因及可选替代技能，不进入默认精选；撤回保留说明页面并停用安装入口，不靠删除页面隐瞒原因。平台撤回不会自动删除员工已安装的文件；遇到已知撤回内容，安装指引要求停止新安装。用户自行升级或移除仍通过 Agent 明确执行。

## 6. 验证模型

| 层次 | 检查内容 |
| --- | --- |
| 条目 | 字段、唯一 ID、来源定位、路径和安装声明完整性 |
| 获取 | 指定版本可取得，技能目录和引用文件完整 |
| 安装 | 指定 Agent/系统中安装、识别、重复安装和冲突行为 |
| 行为 | 一个代表性任务中技能被实际使用，结果满足明确验收条件 |

各层分别展示，不以链接有效代替安装通过，也不以安装通过代替行为有效。验证记录绑定技能 ID、实际源版本、安装声明版本、Agent 版本、环境、执行时间、各层结果和证据位置。

状态区分未验证、通过、失败、环境受限及结果过期。缺少凭据、硬件或网络时不能显示通过。正文或安装方法变化后，旧结果只作为历史证据保留。外部源定期检查和安装验证的任务频率由部署配置控制。

验证按变更影响触发，未变化的相同版本、安装方法和环境可复用已有证据；发现更新时标记新版本待验证，不强制维护者逐个安装重测。周期巡检自动更新可用性，短暂故障先重试，持续故障或需要决策的问题才聚合通知维护者。同一异常在状态未变时不重复催办；精选、常用技能优先安排验证，其他技能允许保持明确的待验证状态。

## 7. 跨安全区信息获取与增量输出

整体方向仍是高区主动读取蓝区信息，再在本区分享到群；本期实现信息准备部分，实际提交给 bot 后续确定。浏览静态站点及读取静态 feed 无需 AccessToken；直接读取非公开仓库时才配置相应读取权限。

Python 模块负责获取已发布信息、格式及引用检查、按用途/技能/变更类型和有效状态筛选、增量判断、去重、相关事件合并，以及生成可供下游直接消费的结构化结果。只有网站发布成功的内容才进入增量来源。

每条输出包含稳定 ID、技能/推荐引用、变更类型、标题摘要、来源版本、详情与安装说明链接、当前状态。新收录与同次首次推荐可合并为一条信息，多技能推荐作为一个主题条目输出；普通编辑不产生新的主动推荐，撤回作为明确变化提供。

输出批次可重取，读取或写入失败不能静默吞掉增量。调用方确认已接收批次后才推进交接进度；这个确认不代表已发群，也不由本模块承担群发送成功的判断。信息获取、筛选规则和进度保存在运行区域，不要求回写蓝区。

本期容错覆盖读取超时/限流/临时故障、数据无效、版本不支持、日志缺口、重复事件、写入中断和进程重启。下游将来可使用 SDK 或 HTTP 发送同一输出；群凭据、签名、平台卡片、发送限流和回执届时设计，不建设当前没有使用对象的通用发送框架。

## 8. 动态信息与区域边界

- 首版优先展示验证状态、最近验证时间和来源可用性。
- 上游 Star 优先采用可选托管动态 badge，标明统计对象是上游仓库；不自行采集、不维护计数、不显示未知采集时间。所在区域不可访问时关闭 badge，保留来源链接；结构化采集与排行不属于首版。
- 内部推荐人数需要身份去重和本区存储，作为后续能力；首版使用经过维护者审阅的推荐理由。
- 复制次数仅表示安装意向，不能标为安装人数；真实使用人数首版不采集。
- 高安全区反馈、推荐记录和统计不默认回流蓝区。跨区汇总需要另行确定允许流转的数据和流程。

后续推荐采用独立推荐帖，不要求改动技能内容。首次贡献的可选理由可转换为推荐帖，员工后续也可通过 Agent 提交新推荐。同一技能可有多篇推荐，一篇主题帖可关联多个技能；普通编辑不重复群发。推荐文章数不等于推荐人数，推荐内容、通知事件和个人点赞分别建模。具体数据字段、发布状态和 badge 策略见技术设计第 13 节。

推荐帖草稿不出现在网站或搜索中；提交发布的内容只有网站实际发布成功才算已发布。撤回推荐后保留撤回说明并从尚未交接的推广输出中排除，并提供撤回变化；已交接或以后已发群内容的处理由下游负责，不承诺远程删除。涉及已撤回技能的多技能推荐可保留历史正文，但停用受影响技能安装入口，不再作为主动推广候选。

## 9. 现有系统调整边界

现有 Registry 以本地 SKILL.md 和内容摘要为前提，不能直接把 external URL 填入旧模型就认为支持外部引用。新条目需区分 hosted 的正文校验与 external 的引用、获取和安装校验。

已确认仓库策略：保留现有仓库和 Git 历史，在新版开发分支建设新系统；旧版用固定标签保留，新版最小闭环完成后通过迁移 PR 切换主线。新版不长期保留 legacy 目录或两套运行时，不为已退出范围的 Profile、Hook、MCP 命令建设长期兼容层。

保留自研技能和新需求/技术文档，按需复用来源解析、路径检查、正文解析、摘要及对应测试。旧运行时、配套命令、Demo、安装脚本和测试在切换时清理或按新版用途重建；旧文档可从旧版标签与历史访问，新版仅保留必要演进说明。

已有外部快照转换时，先建立对应 external 条目并确认来源、安装定位和验证记录，再移除受影响的快照；同步处理旧 Catalog、Profile 和测试引用，不能只删正文。该文档不执行任何迁移或删除。

旧安装入口跟随 main，切换前必须提供指向旧版固定标签的可用入口和迁移说明，避免旧用户无提示进入不兼容的新系统。不重写历史；移除快照指从新版工作树清理，不承诺清除历史版本中的文件。

## 10. 首版验收与实施拆分

验收条件：

1. hosted 和 external 各至少一个条目能贡献、校验、发布、搜索和打开详情页；external 正文不进入仓库。
2. 安装指引能明确指定来源、版本与范围；代表性技能有真实安装和识别证据。
3. 待验证、环境受限、失败和历史验证结果在网站上准确区分。
4. 网站未发布成功时不产生可消费的新技能通知。
5. 本期验证无需 Token 的静态 feed 读取、信息校验、筛选、增量、去重、结构化输出、交接确认和故障恢复；通过 fixture/本地 feed 完成，不要求 bot 桩或真实群。
6. 不要求高安全区写回蓝区，不把高安全区互动数据发布到蓝区。
7. 不熟悉 Git 的员工只提供技能链接即可完成一次推荐提交，不被要求填写维护模板或指定维护人，并能得知处理状态。
8. 员工以一个真实工作目的查找技能，无需理解 L1–L5；也能从群分享或主题精选发现此前不知道的技能。
9. 从技能卡片可直接复制安装指引，在支持且具备必要权限的环境中，由 Agent 完成安装检查并给出首次使用示例；不强制先配置平台运行时。
10. 对来源结构受支持、信息完整的外部技能，系统从链接生成可审阅条目及检查结果；维护者只需审阅与合入，无需逐字段填写、手动发布或转发。不支持的来源明确进入异常队列。
11. 员工把技能来源与贡献指引交给已有 Agent，即可生成符合 Schema 的条目及真实检查结果；hosted/external 各验证一例。无需员工手工编辑元数据，也无需先部署中心化提取服务；无提交权限或不允许跨区写入时，准确保留本地成果并报告下一步，不宣称已提交。
12. 新技能、新推荐、信息修正三种贡献均可进入 PR；重复收录关联既有条目，后续推荐不会被错误拒绝为重复技能。
13. PR 已合入但网站发布失败时显示发布受阻，不推群、不让员工重复投稿；重试成功只产生一次逻辑发布。
14. 推荐普通编辑不产生重复推广；新技能及首次推荐合并成一条输出；多技能推荐作为主题条目；撤回内容不继续进入未交接的推广输出。
15. badge 关闭或失败不影响发现与安装；不显示伪造的 Star 数值、采集时间或人数统计。
16. 草稿不可在网站、搜索或机器可读发布索引中发现；已弃用与已撤回状态、替代入口和失败提示可理解。
17. 起始数据为 5–10 个经调研筛选的开发者技能，主题与用户偏好一致；候选调研记录保留来源、日期、限制和采纳/暂缓理由，不把 Star 当使用人数。
18. 用干净配置的 Luna 完成安装、调用校验器和代贡献验证；优化员工可获取的提示词和仓库资源，并比较成功率、调用次数、人工介入、耗时和可取得的用量；独立检查结果，不泄露测试答案。

通过小规模员工试用观察推荐所需输入、从看到技能到开始尝试的操作步骤、安装失败后的人工介入和重复通知反馈。同时观察每条常规推荐的维护者操作数、人工处理时间和异常队列积压，以端到端总成本评价设计。首版以任务观察与自愿反馈验证成本是否降低，不为衡量这些目标引入强制客户端遥测。

建议按依赖拆分实施：先做技能/推荐模型及贡献契约，再做网站与安装说明，随后连接验证记录与发布事件，最后完成 Python 信息提供与部署指导；bot 提交后续对接。技术设计给出推荐技术栈；最终版本和内部部署、Git/CI、群平台仍需适配实际设施，不影响已确认的主动拉取方向。
