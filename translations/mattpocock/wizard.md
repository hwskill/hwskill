# 向导

**向导**是一段 Bash 脚本，逐步引导人完成手工执行很繁琐、每次向 AI 重述也很繁琐的流程。它会打开每个 URL，准确说明要点击和复制什么，收集值并写入正确位置（`.env`、GitHub secrets），在每个阶段要求确认，并显示剩余阶段数。它可以配置第三方服务、执行一次性迁移，或把项目从一种状态转换到另一种状态。

[template.sh](template.sh) 已经解决了良好体验：逐阶段进度、确认门禁、跨平台打开 URL（包括 WSL）、隐藏输入秘密、幂等更新 `.env`、写入 `gh secret`/`gh variable`，以及结束摘要。**你的任务只是在限定流程范围并编写各阶段。**`STAGES` 标记上方的库在每个向导中都完全相同；一致性正是其价值，绝不要手工修改。

向导默认是临时制品：为一次运行而建，保存到临时路径或 `scripts/` 路径，工作完成后删除。只有用户希望仓库长期保留可重复的设置路径时才提交。

## 流程

### 1. 限定流程范围

找出人必须执行的每个手工步骤以及期间要采集的每个值。先读取仓库，不要直接询问：

- 对于设置流程：检查 `.env`、`.env.example`、`.env.*`、`README`、`docker-compose*`、框架配置和 `.github/workflows/*`（每个 `secrets.*` 或 `vars.*` 引用都是向导必须产出的值）。
- 对于迁移或转换：检查当前状态、目标状态以及两者之间的不可逆操作。

随后向用户展示按顺序排列的阶段和每阶段产生的值，并请求确认；用户可以增加、删除或调整顺序。

**完成条件：**每个阶段都已按顺序命名，并且每个采集值都明确：(a) 人从哪里获取，(b) 写到哪里（`.env`、GitHub secret、两处都写或不写；有些阶段只有动作），以及 (c) 它是秘密（隐藏输入）还是公开值。

### 2. 映射每个阶段的操作路径

为每个阶段写出人要遵循的精确路径：打开哪个 URL、在那里做什么、值显示在哪里、填入哪个变量，例如“Dashboard → Developers → API keys → Reveal test key → 复制”。如果不知道当前 UI 或准确命令，就明确说明并询问用户或查阅文档；绝不编造可能不存在的步骤。

**完成条件：**每个阶段都能追溯到陌生人也可以执行的具体说明。

### 3. 编写向导

把 `template.sh` 复制到目标路径。用按依赖顺序排列的 `stage` 替换示例阶段，每步一个。使用库中的辅助函数：`stage`、`say`/`step`、`open_url`、`ask`/`ask_secret`、`write_env`、`set_secret`/`set_var`、`pause`/`confirm`。把 `TOTAL_STAGES` 设置为实际阶段数。

保持模板设定的标准：先打开 URL 再请求值；所有秘密使用 `ask_secret`；所有持久值使用 `write_env`；只有 CI 实际需要的值才使用 `set_secret`；不可逆操作前使用 `confirm`。每个 `stage` 会清屏，只显示当前步骤，因此一个阶段只做一项聚焦任务，避免人所需内容滚出屏幕。不要修改标记上方的库。

### 4. 验证并交接

- 运行 `bash -n <script>`；如果有 `shellcheck`，也要运行。
- 运行 `chmod +x <script>`。
- 不要自行端到端运行，因为它会打开浏览器并等待人输入。改为静态追踪：步骤 1 的每个值都得到采集并写到指定位置，每个 `set_secret` 名称都与 CI 中的 `secrets.*` 引用完全一致。
- 告诉用户如何运行。如果这是可重复的设置路径，就提交脚本并在 README 中链接，使下一位使用者直接运行脚本，无需再次询问 AI。
