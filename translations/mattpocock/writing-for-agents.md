这是一份编写 Agent 所消费文档的参考：技能、`AGENTS.md`/`CLAUDE.md`，或由指针指向的文档。包装方式不同，写作规律相同：同样的杠杆使它们可预测，因为 Agent 每次遵循相同**过程**，而不是每次产出相同结果。

编写技能时，阅读 [`SKILL-MECHANICS.md`](SKILL-MECHANICS.md)，了解 frontmatter、调用方式选择和路由技能。

## 上下文指针

**上下文指针**是 Agent 上下文中的一个引用：它命名上下文外的材料，并编码何时访问该材料。技能 description 是一个指针；`AGENTS.md` 中命名某份文档的一行也是同类对象。决定 Agent 何时以及多可靠地读取材料的是指针的**措辞**，而不是目标本身。必需材料隐藏在措辞薄弱的指针后面会产生方差缺陷：先强化措辞，只有仍然失败时才把材料内联。

指针有两个作用：说明材料是什么，并列出应触发读取的**分支**（分支是文档处理的一种独立情况，因此不同运行会走不同路径）。常驻指针中的每个词都会在每轮付出成本，所以它比正文更需要修剪：

- **把引导词放在最前面**：指针正是在这里发挥触发作用。
- **每个分支一个触发条件。**只是重命名同一分支的同义词属于重复，应合并，只保留真正不同的分支。
- **删除正文已经携带的身份说明。**

## 两种负载

每增加一份文档或指针，都消耗以下两种预算之一：

- **上下文负载**是常驻材料对 Agent 窗口的成本：`AGENTS.md` 中的一行、技能 description，或任何每轮都在上下文中的内容，无论是否触发都会消耗 token 和注意力。
- **认知负载**是人的成本：有哪些文档，以及何时使用。人就是索引。这不是必须最小化的成本，而是人拥有自主判断的代价；在人类判断重要的地方保留，在不重要的地方移除。

只有通过指针才能访问的材料以指针一行的成本避开上下文负载；完全没有指针的材料则完全依赖认知负载。

## 信息层级

文档由两种内容组成：**步骤**（Agent 按顺序执行的动作）和**参考**（按需查阅的定义、规则、事实）。两者可以自由混合：全是步骤（配方）、全是参考（评审规则或本技能），或两者都有。核心决定是每项内容在**信息层级**中的位置。该阶梯按 Agent 需要材料的即时程度排序：

1. **文件内步骤**是首要层：Agent 按顺序做什么。
2. **文件内参考**按需查阅。它常常是合理的扁平同级集合，例如评审中的每条规则位于同一层级；这种结构本身不是问题。
3. **已披露参考**被移到独立文件，通过上下文指针访问，只有指针触发时加载。范围可以从同目录兄弟文件延伸到任何文档都能指向的完全外部参考。

下移太少会使顶部臃肿；下移太多会隐藏 Agent 实际需要的材料。这种张力就是设计的核心。

**渐进披露**是沿阶梯下移（离开主文件并置于指针之后），使顶部保持清晰。它主要不是 token 优化，而是保护信息层级。分支是最清晰的披露测试：每个分支都需要的内容内联，只有部分分支使用的内容放到指针后。对于含步骤的文档，本应披露的文件内参考会埋住步骤，让 Agent 是否注意到步骤近似随机；这不仅影响可读性，也会影响方差。

**并置**是文件内部的配套原则：阶梯决定内容下移多远，并置决定到达该层级后哪些内容放在一起。把一个概念的定义、规则和注意事项放在同一标题下，不要分散，这样阅读一部分会同时带出邻近内容。判断方式是：文档应读起来像专为 Agent 编写的文档。成组内容符合这种感觉，分散内容不符合。（它不同于重复：重复是在两处表达同一含义，分散则把一个含义拆散到许多地方。）

**蔓延**是另一种失败模式：文档太长，即使每行都有作用且不重复。过量内容会稀释注意力，每多一行都增加维持相关性的成本。解决方式是使用阶梯：把参考披露到指针后，按分支或顺序拆分，使每条路径只携带所需内容。

## 步骤和完成条件

每个步骤都以一个**完成条件**结束，告诉 Agent 工作何时完成。两个属性使它发挥杠杆作用：

- **清晰度**：Agent 能否判断完成与未完成？“已经理解”之类模糊边界会诱发**过早完成**：步骤尚未真正完成，注意力却转向结束。仍然可见的后续步骤（**完成后步骤**）提供拉力，完成条件的清晰度提供阻力。按顺序防御：先**明确边界**（局部且成本低）；只有边界无法进一步明确且确实观察到赶进度时，才拆分序列以隐藏后续步骤。隐藏只有跨越真实上下文边界才有效（交接或子 Agent 派遣）；内联调用仍保留后续步骤，不会清空上下文。
- **要求强度**：条件要求完成多少内容。“覆盖每个修改过的模型”会迫使工作彻底，“生成变更列表”则不会。要求强度驱动**查证工作**，即措辞中隐含而非单列为步骤的深入查找；它也不局限于步骤：“应用每条规则”可以约束一组扁平参考，就像“完成每个步骤”约束序列，因此纯参考文档也能有完整性门槛。

最强的完成条件既可检查又穷尽范围。

## 何时拆分

把一份文档拆成两份会消耗两种负载之一，因此只有收益足够时才拆：

- **按顺序拆分**：一连串步骤中，后续步骤会诱使 Agent 草率完成当前步骤时拆分。让后续步骤暂时不可见，会推动当前任务投入更多查证。反向风险也存在：合并序列会让每个步骤看到之后的内容，诱发过早完成。
- **按调用方式拆分**：技能特有方式见 [`SKILL-MECHANICS.md`](SKILL-MECHANICS.md)。

## 引导词

**引导词**是模型预训练中已经存在的紧凑概念，Agent 执行文档时会用它思考，例如**课程**、**战争迷雾**、**曳光弹**。它以 token 形式反复出现，而不是重复整句；借助模型已有先验，用最少 token 积累分布式定义并锚定整片行为。自创词在定义清楚时也能工作，但自造词不会调用已有先验：预训练词免费提供的内容需要你用定义 token 补齐，因此应先寻找已有词。

它会锚定两次。在正文中锚定**执行**：Agent 每次看到该词都会调用相同的行为，在扁平参考中把注意力聚焦于某类目标。在指针中锚定**调用**：相同词同时出现在提示、文档和代码库时，Agent 会把共享语言与材料连接起来，更可靠地访问它。

主动寻找用引导词重构的机会。一组三项内容在三处分别写出，或指针用一句话绕着一个概念描述，都适合收缩成一个 token：

- “快速、确定、低开销” → **紧密**（一个**紧密**循环）。
- “一个你信任的循环” → **红**，把模糊门禁转换为二元可观察状态（循环会在缺陷上变**红**，或者不会）。

收益有两层：token 更少，Agent 的思考挂钩更明确。假设每份文档都有可由引导词替代的重复表述，并主动寻找。

**否定句**是相邻的失败模式：用禁止项引导会把被禁止行为带入上下文，使它**更容易**出现。“不要想大象”后，注意力里只剩大象；否定词是微弱修饰，无法压过已被强激活的概念，因此禁令可能被半读成执行指令。应使用**正向**提示：说明目标行为（“写一行注释”），不让被禁止行为进入表述。只有无法改写成正向表达的硬护栏才值得使用禁止句；即便如此也要搭配正向目标，让注意力落在应做的事情上。

## 修剪

- 让每个含义只有一个**单一事实来源**：一个权威位置，使行为变化只需修改一处。**重复**（同一含义出现在多个位置）会增加维护和 token 成本，并把该含义在阶梯上的显著性抬得高于真实等级。（它是引导词的偶然反面：引导词有意重复一个 token，却不重复含义。）
- **环境**也是事实来源（`package.json` 脚本、配置文件、目录布局、`--help` 输出）。重述环境的文档是一份**缓存**：复制一次查询，只有查询本身代价高时才值得承担负载。只缓存 Agent 无法通过查看获得的内容：未成文约定、选择背后的理由、配置无法揭示的陷阱。单文件、单命令可以查到的信息留在环境中，避免过时。
- 检查每行的**相关性**：它是否仍与文档工作有关？一行内容可能从未真正影响任务（纯说明或本应披露的分支），也可能因行为或外部世界变化而过时。短文档更容易保持相关。没有修剪纪律时，默认结局是**沉积物**：陈旧层不断堆积，因为添加让人安心，删除让人不安，最终必须钻过多层才能找到仍然有效的内容。
- 逐句寻找**空操作**：如果模型默认已经遵循某条指令，它就只消耗负载而不改变行为。判断标准“相对默认行为是否有变化”取决于模型而不是读者；两个人对空操作有分歧，其实是在争论默认行为，应通过运行文档解决，而不是讨论。句子未通过测试时，删除整句，不要只缩短。该测试也适用于引导词：弱到无法改变默认行为的词（Agent 本来就会“比较彻底”时仍写“要彻底”）属于空操作；解决方式是使用更强的词（“持续追问”），而不是改用其他技巧。
