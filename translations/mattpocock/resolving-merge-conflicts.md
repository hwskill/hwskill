1. **查看 merge/rebase 当前状态。**检查 Git 历史和发生冲突的文件。

2. **找到每处冲突的一手资料。**深入理解每项变更为何产生以及最初意图。阅读提交消息、PR 和原始 issue 或工单。

3. **逐个解决冲突块。**尽可能保留双方意图。两者不兼容时，选择符合本次合并既定目标的一方，并说明取舍。不要发明新行为。始终完成解决，绝不运行 `--abort`。

4. 找出项目的**自动检查**并运行，通常依次为类型检查、测试和格式化。修复本次合并造成的所有问题。

5. **完成 merge/rebase。**暂存全部内容并提交。如果正在 rebase，继续整个 rebase 流程，直至所有提交都完成变基。
